# PM18：可替换判断服务已实现

本轮将用户确认的借鉴方向落实为版本化银行任务边界和本地判断服务。判断内核、业务处理策略、工作台及审计分别承担明确职责。

## 已完成的业务路径

材料归集 → 原输入规则检查 → Jev式候选判断 → 原文证据与处理待办 → 人工复核 → 本地结果交接。

缺项仍先补件。服务异常时，事项与原文保留为待人工处理；不能以模型不可用为由自动通过，也不回退到预设仿真答案。复杂分析仍由原双系统实验模式显式启用。

两项核验分别使用 `USE_MATCH@1.0.0` 与 `BIZ_CONFLICT@1.0.0`。任务文字、候选顺序和原模型推理未改。业务规则和人员责任不由服务端自由决定。

## 对mu核心代码的采用决策

采用其“版本化判断点、可替换后端、策略与判断分离、来源留痕”的架构设计；本轮没有安装mu依赖或执行其Agent代码，也不引入公共免费判断路由。当前标准库服务即可承接现有银行原型，暂不依赖 `@kyrn/judge`。

两个首期任务都涉及材料关系。以后更换Laya、其他SLM或官方Jev时，要按相同任务契约验证中文材料、候选分布、来源、异常处理与领域效果。能力声明只是适配条件，不能替代业务实验。判断器级联也不能自动写作已接入工银智涌的慢思考。

## 尚待验证的业务增量

本轮证明的是接口可替换和闭环保持。模型仍未经信贷领域训练或校准，历史语义错误与52份开发负结果不因工程改造而消失。本次真实冷启动加载331.2秒，补件重跑端到端约13.3秒，仅为本机工程观察；不构成时延承诺，更不能沿用“200ms、降本75%”作为当前成绩。

G1领域可靠性、G2独立标签、G3合理对照与完整收益评价仍按原台账推进。下一动作是根据新增接口锁定领域候选与同任务对照，不继续移植无关编程Agent功能；缺独立业务复核时只做开发诊断。

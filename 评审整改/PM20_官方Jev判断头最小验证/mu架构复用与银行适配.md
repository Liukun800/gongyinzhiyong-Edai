# mu 架构复用与工行贷前场景适配

核查对象为 PM17 固定提交 47c51b0c68f622e9953b7f501d165fe474eec588。此次未更新该仓库快照，也未将作者通用实验当作信贷实验。

## 可复用与需改造的边界

| mu 组件 | 银行映射 | 当前执行方式 |
| --- | --- | --- |
| DecisionSpec、state、questions | 版本化用途/经营任务与材料状态 | PM18 已独立实现两项任务契约；PM20 采用官方 Choice 协议 |
| TypeSafeJudgeProvider | 官方 Jev 判断头服务 | 复用 HTTP 协议形状；本轮独立 Python 实现，不依赖 mu 编程扩展 |
| Policy、fallback | 按业务事实与风险门禁分流 | 不照搬默认阈值；缺件先补充，矛盾交人工，复杂事项再分析 |
| off / shadow / active | 关闭、旁路记录、有限辅助采用 | 作为后续银行适配策略；不把它等同于 Demo 的模拟/真模型模式 |
| Ledger、stateDigest | 材料/模型版本与人员责任记录 | 以 PM18 现有事务台账承接，审计失败阻止采用建议 |
| Cascade | 判断后端级联 | 仅作为候选；两个判断器级联不等于工银智涌慢分析 |
| 编程工具、浏览器、子代理扩展 | 与首期贷前任务无直接关联 | 本轮不引入，保留自己的业务工作台 |

## 必须保留的场景设计

1. 两项任务的主体、期间、资金范围、有效材料和候选答案定义。
2. 独立原文索引；模型给出候选判断不等于证据已获核实。
3. 材料补件与新版本重跑，历史建议不覆盖当前材料结论。
4. 客观缺件、语义不足、明确矛盾与服务异常分别处理。
5. 模型不可用时真实标记失败并交人工，不把占位中性答案写成模型判断。
6. 审计写入失败不继续采用建议；最终授信责任沿用既有授权。

## 直接复用代码的实施建议

mu 判断包声明 MIT 许可，根 LICENSE 要求保留版权及许可声明。若后续直接复用 TypeScript 内核，应固定提交、保留 LICENSE 与相关第三方声明，隔离核查 Node 版本和依赖，并对银行任务、失败与台账规则建立回归。PM20 当前仅复用协议和设计思想，代码为独立实现，因此不能描述为“mu 内核已接入银行”。

计划书强调的贡献是：将通用判断编排收敛为贷前材料核验任务，使建议、证据、版本、人员动作与后续审查连续交接。现有 Demo 不必推翻；更换判断后端时保持业务工作台和既有结果承接协议。

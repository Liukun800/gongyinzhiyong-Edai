# 官方 Jev 判断头最小验证

本包依官方 TypeSafe System One 协议独立编写，mu 仅提供编排与适配思想参考。默认 Demo、旧实验与原计划书保持。

## PowerShell 配置

在自己的 PowerShell 窗口运行：

```powershell
& 'D:\jev工行杯\评审整改\PM20_官方Jev判断头最小验证\配置官方Jev.ps1'
```

脚本复用当前窗口已有的 JEV_API_KEY 或 TYPESAFE_API_KEY；缺少时隐藏输入一次。密钥只保留在该窗口环境中，不写入文件、用户环境、命令历史或日志。关闭窗口后需重新配置。默认地址与模型为官方 System One 和 jev-latest；已有配置保留并由客户端校验。本步骤仅进行本地配置检查，网络调用为0，不代表密钥已通过官方认证。

配置后要直接运行两条仿真验证，可在同一窗口执行：

```powershell
& 'D:\jev工行杯\评审整改\PM20_官方Jev判断头最小验证\配置官方Jev.ps1' -RunMinimum
```

真实调用成功后自动执行离线结果验收并生成简报；失败停止，不自动重试。请不要把密钥或含密钥的截图发送到聊天。

在已配置密钥的 PowerShell 窗口执行：

```powershell
& 'D:\jev工行杯\评审整改\PM20_官方Jev判断头最小验证\开始官方最小验证.ps1'
```

只运行两条自编仿真任务，最多两次 HTTP 请求，不重试、不跑批。需要 JEV_API_KEY 或 TYPESAFE_API_KEY；地址和模型缺省采用官方 https://api.typesafe.ai/v1/systemone 和 jev-latest。原有地址只能属于官方域名，防止误向其他服务发送凭据。

使用 state + questions，不使用 chat/completions、文本理由或报告生成协议。Choice 候选由 criteria 定义；响应严格检查模型身份、任务身份、概率归一性、选择与最高概率一致性及用量。错误只保留类别和状态码，不保留服务器报错原文、认证头或凭据。

响应另存于每次独立 run 目录。证据编号由材料索引提供，模型置信度不等于正确率；全部结论保留人员复核。两例通过仅代表协议闭环，不形成银行准确率、经济收益或生产接入结论。

## 结果验收与简报

调用完成后执行以下命令，自动检查最新完整结果，并在同一 run 目录生成 `validated_report.json` 与 `官方最小验证简报.md`：

```powershell
python -X utf8 'D:\jev工行杯\评审整改\PM20_官方Jev判断头最小验证\summarize_minimum.py'
```

该步骤不调用网络。检查任务身份、冻结材料与问题、响应格式、参考标签一致数、Token总量及失败接管。原始请求和响应保持；已有验收报告内容变化时拒绝覆盖。没有完整输出时仅报告待执行，不产生模拟实验简报。新增5项验收测试与原有10项协议测试共15项通过，均为离线测试。

## 领域适配

官方 Jev 通过状态结构、任务说明和候选判定标准适配业务；本地 AgentJev 训练任务头属于另一条实验路线。官方服务不提供本项目自定义权重训练，不能将社区微调实验说成官方 Jev 微调。

对客户材料的银行环境验证，应采用银行批准的数据与部署条件。本实验仅发送包内自编仿真文本。

# 方法论

本项目面向数字金融赛道，研究贷前材料归集后、综合审查前的辅助核验。研究对象是可嵌入现有业务流程的任务组件，其价值需要与银行既有能力按同任务比较确认。

## 从业务问题定义判断任务

先确定谁使用、比较什么材料、判断针对哪个主体和期间、结果由谁承接，再选择模型。首期保留两项任务：资金用途一致性和经营陈述矛盾识别。每项任务具有明确的材料范围、候选结论、原文位置和后续处理动作。

行业公告与政策要求用于说明背景。它们不能单独证明工小审存在具体能力缺口。新增组件的必要性应通过业务任务清单与同任务比较确认，包括既有能力覆盖、查证耗时、异常处置与结果交接。

## 将判断与生成分工

Jev 的产品定位是结构化判断。官方服务与社区 Jev-like 模型分别记录，社区模型的结果不能称为官方 Jev 成绩。Jev式任务范式、SLM/LLM模型规模、Transformer网络结构属于不同维度。

采用专门判断后端的设计动机是：当任务可以表达为有限候选时，直接形成可检查的判断结果；需要分析复杂关系时，再协同生成式模型。它支持明确的业务分工，但模型规模、预训练、硬件和输入方式都会影响实际质量与成本，收益必须实测。

快思考承担限定任务判断，慢思考承担具备充分材料的复杂分析。模型结果始终保留版本及证据位置，最终授信决定沿用银行原有授权。Jev不替代工银智涌，也不承担贷款自动批准。

## 依据任务原因选择承接路径

| 原因 | 承接方式 | 设计依据 |
| --- | --- | --- |
| 客观缺件或口径不可比 | 补充材料或澄清口径 | 模型分析不能补出不存在的事实 |
| 材料充分且限定判断明确 | 形成核验建议与证据索引 | 判断完成不等于授信审批完成 |
| 材料充分但关系复杂 | 按任务条件进入复杂分析，再复核 | 升级需要证明有助于纠错 |
| 存在明确矛盾 | 人工核实与责任记录 | 矛盾属于业务事项，不能仅以模型解释消除 |
| 服务失败、分布非法或审计失败 | 明确失败并转人工或停止采用 | 不使用预设答案冒充推理 |

置信度是路由的候选信息。未经校准的分数不能作为自动接受条件。历史实验中的阈值只属于开发配置，银行使用条件需事先登记并独立验证。

## 用同任务验证增量

对照应共享材料、任务说明、候选定义、输入检查与错误代价。材料与参考标签分开保存，派生案例按案例族隔离，训练折外的材料不得进入拟合。已经查看结果的资料转为开发回归资料，不能反复称为未见测试。

先报告误报、漏识别、信息不足和失败，再报告总体参考一致数。双系统按逐例配对报告纠错、新增错误、正确保持、错误保持，同时检查未升级路径中的错误。领域标签未经独立业务复核时，结果只能作为开发诊断。

新增组件的采用条件包括：质量达到预登记要求、关键错误可控、证据与交接完整，以及完整成本或人员负担具有增量改善。若既有能力已经覆盖任务且新组件没有实测增量，应保留既有处理路径。

## 测量完整业务收益

完整成本包括材料整理、规则与快判断、复杂分析、人工复核、失败重试、部署维护及审计。分别记录机器处理时延、排队与重试、人员有效操作工时和完整处理时间。减少调用次数或生成Token只能说明资源使用变化，不能直接换算降本、审批提速或风险改善。

## 按证据推进实施

本地原型用于验证流程；领域对照用于选择候选能力；独立业务复核用于确认任务标签；银行受控离线比较用于确认适配和增量；有限辅助使用需通过银行授权及质量门禁。各阶段保留失败与负结果，不用下一阶段的规划替代当前证据。

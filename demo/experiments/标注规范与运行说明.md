# 首批仿真开发材料与标注规范

版本：dev-v1；日期：2026年9月27日。

## 1. 数据用途

本批包含24份任务材料包，每包执行一个任务：用途一致性12份、经营矛盾12份。每项任务的三个候选类别各4份，按6个案例族组织，每族2份。数据由项目编制，为功能开发、错误分析和初步对照服务；标签尚未经银行专家独立审核。它不是银行业务抽样，不反映真实类别分布，也不是最终测试集。

已有D02错误结构包含在B03中，标明为已知开发回归案例。任何依据本批材料调整的问题模板、规则、参数、训练或阈值，都不能再以同批材料证明独立泛化能力。

## 2. 文件隔离与复现

- development_cases.json：仅材料输入、任务编号和本地记录编号。
- development_labels.json：参考答案、案例族、依据、预期处理动作及来源声明。
- dataset_manifest.json：文件哈希、版本和计数。
- build_development_set.py：逐份材料编制脚本；修改数据后需要提高版本并重新审查标签。
- run_development.py：执行规则基线、分案例族交叉验证的普通分类器、真实AgentJev诊断。
- results/development_comparison.json：完整结果、训练/验证编号、模型版本、逐条错判及实际请求统计。

在demo目录运行系统Python：

```powershell

```

需先启动8767端口真实影子服务。仅运行本地普通分类器可加`--skip-real`。接口`POST /api/shadow/evaluate`只接受documents和task_ids，不接受预期答案；运行不改工作台案例、版本、复核及历史。评估器本地持有标签，预测完成后才比较。

## 3. 判定顺序与标签口径

先确认主体、任务对象、期间和所述范围，再比较有效材料中的陈述。登记字段只用于先行检查；登记与正文不一致仍需语义处理。有效性在仿真材料中属于明确题设，模型不验证签名、合同效力或交易真实性。

| 任务 | 标签 | 规则 |
|---|---|---|
| 用途 | 一致 | 对应同一申请，给定材料支持待核验的完整用途范围，未发现互斥陈述 |
| 用途 | 存在明确矛盾 | 同申请、同范围、当前有效陈述互相排斥；不能仅因出现不同商品即判矛盾 |
| 用途 | 信息不足 | 缺件、对应申请不明或不同、只覆盖部分用途、无法确定有效版本 |
| 经营 | 发现明确矛盾 | 同主体、重合期间、同经营范围内的陈述不能同时成立 |
| 经营 | 未发现明确矛盾 | 给定可比陈述相容，或有效更正消除了原冲突；不推断经营风险低 |
| 经营 | 无法比较 | 主体或期间不匹配、资料缺失、比较范围无法明确 |

证据必须精确匹配材料编号、段落编号和原文。不能把“引用存在”计作“引用支持答案”；后者由参考标注及复核单独检验。

## 4. 处理动作

明确矛盾转人工核实；缺失或不可比进入待补充；一致或未发现矛盾仍待复核。人工可更正任务答案并说明依据；补充或编辑材料生成新版本。任何动作均不代表审批通过。本批不设置自动完成阈值，也不进行信用风险概率估计。

输入字段非法、返回格式错误、异常概率、模型失败属于工程错误，不记成正常的“信息不足”答案。规则识别的缺件、主体或期间问题可以产生不足类结果，来源须明确标为input_rule，并计入规则分流。

## 5. 对照与分组

普通分类器采用字符2—4元TF-IDF及逻辑回归，按任务分别训练。固定C=1、类别平衡，不以本次结果搜索超参数。每次留出整个案例族，10份训练、2份验证；向量器也只在训练折拟合。24份材料全部属于开发池，这种交叉验证只提供开发诊断。

规则检查、候选集合及答案到动作的映射一致。普通分类器和Jev都展示同一份输入原文，但不把输入原文展示当作已验证的模型解释。普通分类器是已实现的基础对照，尚不能代表调优中文编码器的最佳水平；后续必须加入中文编码器分类器及规则＋大模型对照。

## 6. 本批不能证明什么

不能据24份人为平衡材料推断银行总体准确率、人工复核率、真实成本或违约风险；不能将规则命中的正确数归因于模型。不能把全部待人工复核包装为低风险自动化。未完成独立领域校准，不发布具有风险保证含义的置信阈值或ECE结论。

完整训练、校准、路由验证及测试数据须按案例族和派生关系隔离；先划分组，再生成组内变体。最终测试组保留到方案冻结后，且不含本批开发案例、已知错误改写或同模板近重复材料。

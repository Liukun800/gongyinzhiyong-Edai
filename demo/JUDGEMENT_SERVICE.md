# 可替换判断服务

本轮借鉴 mu 的版本化决策点、判断后端与业务策略分离设计，采用独立 Python 实现。工作台、证据定位、材料版本、复核和结果交接继续使用现有流程。没有移植 mu 的编程 Agent、工具执行或公共模型网关。

## 运行

原本地演示仍可运行 `start_presentation.ps1`，默认真实快判断＋人工复核。原上游适配器仍保留。

新增独立服务方式（在 PowerShell 中执行）：

```powershell
& 'D:\jev工行杯\demo\start_judgement_service.ps1' -Port 8148
```

等待 `demo/runtime/judgement-8148.log` 出现 `Local judgement ready`，再启动工作台。加载时间与权重校验、CPU及磁盘状态有关，不计为模型推理时延。

```powershell
& 'D:\jev工行杯\demo\start_service_workbench.ps1' -Port 8778 -JudgePort 8148
```

工作台地址：`http://127.0.0.1:8778/`。独立数据库为 `runtime/service-workbench-8778.sqlite3`，不复用旧演示库。首次服务启动自动生成本地令牌文件 `runtime/judgement-service.token`；只供进程读取，不放入报告、截图、版本库或分享包。此为本地演示认证，不能替代银行生产身份权限体系。

结束时可根据对应 PID 文件停止本轮启动的两个进程；不要按进程名称批量结束其他服务。

## 业务契约

- `USE_MATCH@1.0.0`：资金用途说明与证明材料的一致性判断。
- `BIZ_CONFLICT@1.0.0`：同主体同期间经营陈述的矛盾判断。
- 两项均要求 `relate` 类型能力；此为任务需求，不表示现有检查点已通过信贷关系推理验证。
- 当前只实现 Choice 候选判断；没有扩写 Score/Noul 或授信决策能力。
- 模型输入只有材料主体、期间、段落原文；不发送申请编号、参考标签、场景注释或复核反馈。
- 输入缺失由原规则形成补件待办；语义不确定、明确矛盾及服务故障由人员处理。
- 所有模型建议均需人工复核，不设置自动审批阈值，不产生额度、利率或放款指令。

## 接口与后端

`judgement.VersionedJudgement` 包装符合原 `info/decide/decide_many` 协议的判断器，保留原候选计算与批量推理。`judgement_http.HttpJudgement` 接同一任务规范的本地服务。

- `GET /api/info`：协议版本、两项任务定义、策略与模型身份。
- `POST /api/judge`：`{api_version, id, questions}`。每个问题为 `{id, version, question_sha256, state}`；最多两项、不得重复。
- 响应包含请求编号、模型身份、逐任务版本及候选判断。客户端按任务编号归位，检查版本、分布、输入摘要和模型身份。
- 只允许显式 `http://127.0.0.1:端口`，拒绝重定向与代理、浏览器跨域请求；请求和响应各限制1 MiB；超时不自动重试。
- 本契约为本项目的银行任务边界，不宣称与 mu 或 TypeSafe 官方接口直接兼容。原 `UpstreamDecisionModel` 是独立保留的社区上游协议。

本地模型仍为固定版本社区 AgentJev-0.6B。替换其他判断器时，先检查许可证、中文任务能力、接口与同任务对照；不能因为包装成功就宣称金融效果达标。官方 Jev 不在本次运行范围。

## 留痕与故障

逐任务 `decision_record` 包含任务版本、问题摘要、输入摘要、后端及模型身份、复核策略和回退责任。它与材料快照、原始候选结果、人员记录一起持久化到原 SQLite 运行/事件事务，并随本地结果包交接。

工作台只在记录事务成功后返回结果。事件记录失败时回滚本次运行，接口返回503并提示按原流程人工处理。服务不可用时保存未形成判断的任务和原文，不用仿真答案替代。服务启动身份显示不等于持续可用性承诺；运行失败会在具体任务中展示。
